## P3 — bounded `--max-calls` inside `trusted-compiler`

### Problem
`Calls` counts every admitted non-root call over the whole execution (`docs/spec/quotas.md`, "Known compiler-workload blocker"). Native Linux confirmation on `main` @ `94c5c50`: a lexer with one helper call per byte stops at `Calls limit=16384 used=16385` whatever `--max-steps` is. Compiler workloads are therefore capped by call count, not by work.

### Resource-accounting analysis (why a bounded override is coherent)
- **Calls do not drive live memory.** Live memory from calls is bounded by `max_frames` and `max_stack_depth` (≤ 1024 under the envelope). `Calls` is cumulative; a returned frame is released.
- **Calls are dominated by Steps.** Every `CALL` is itself a charged step, so `calls ≤ steps` holds on every execution. A Calls budget above the Steps budget can never be reached. Inside the envelope, `Calls` is therefore an additional time-shaped bound, not a new resource dimension.
- **Calls is not a verifier input.** The verifier must still be shown to receive the identical `ExecutionConfig`, exactly as #2036 established for Steps and Frames. That requires its own test.

### Proposed contract (draft, for OWNER approval)
- `--max-calls <N>` is accepted only with `--envelope trusted-compiler`. Without it, the error is `--max-calls requires --envelope trusted-compiler` (validation rule 8, as for `--max-steps`).
- **Range:** `1..=200000000`, and additionally `N <= effective max_steps`. Otherwise: `--max-calls must not exceed the effective max_steps (<S>)`. This keeps the invariant `calls ≤ steps` explicit and prevents an unreachable, misleading budget.
- **Parsing:** the same decimal-only rules as `--max-steps` (validation rules 3, 6, 7).
- **Unchanged:** `max_effect_calls`, `max_registers` and `max_symbol_table`. The context stays `VerifiedLocal`. No capability is granted.
- **Metrics:** `effective_quotas.max_calls` already reports the value; no schema change.
- **Tests:** the Q-matrix analogue of Q-04/05/38/39/40 for Calls:
  - exact and limit+1;
  - overflow and non-decimal input;
  - the ordering rule against `--max-steps`;
  - verifier/runtime coherence;
  - defaults unchanged, Q-01/Q-02.
- **Rejected alternative:** redefining `Calls` as call depth. It changes the meaning of an established quota for every profile.

2. Confirm that the `max_calls` blocker text in `quotas.md` is updated in the same PR.
